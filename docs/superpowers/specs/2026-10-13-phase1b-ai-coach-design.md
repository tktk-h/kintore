# フェーズ1b AIコーチ 設計書

作成日: 2026-10-13（同日改訂：メニューの決め方、きつさによる調整）
全体計画: [2026-10-12-kintore-app-roadmap.md](2026-10-12-kintore-app-roadmap.md)

## ゴール
アプリの中でAIと相談しながら、根拠のある組み方で自分に合った1週間分のトレーニングメニューを作り、確認してから予定に反映できるようにする。反映した予定は、ホームの「今日のトレーニングを始める」からそのまま実行できる。記録したきつさをもとに、重さとセット数が少しずつ調整されていく。

## 範囲
**含む**: プロフィールの聞き取り、メニューの骨組みを決める仕組み（分割法・枠・量）、AIコーチのチャット画面、メニュー案カードと反映、重さの自動計算、きつさによる調整、メニュー案のチェック、種目データへの情報追加、きつさの入力の改善、Vercelへの引っ越しとサーバー、合言葉による保護、下部メニューの変更

**含まない**: 休憩終了の通知（別のタイミングで作る）、食事のAI、週ごとの振り返りコメント、代わりの種目の提案（フェーズ5）、ログイン（フェーズ7）

## 決まったこと
| 項目 | 決定 |
|---|---|
| AI | Google Gemini API の無料枠（後から別のAIに乗り換えられる作りにする） |
| 置き場所 | アプリごと Vercel に引っ越す。サーバーは Vercel の関数 |
| 保護 | 合言葉。アプリの設定に入れ、サーバーが照合する |
| 計画の単位 | 1週間ずつ |
| 反映 | AIの案をカードで見せ、「反映する」を押したときだけ予定に入れる |
| 骨組み | 分割法・日ごとの枠・量はアプリが決まったルールで決める。AIは枠に種目を入れ、調整と説明をする |
| 調整の材料 | 種目ごとの「きつさ（5段階）」。セットごとの余力は聞かない |

## メニューの決め方

### 根拠（調査の要点）
- 筋肥大に最も効くのは部位ごとの週のセット数。週10セット前後までは効果がはっきり増え、それ以上は増え方がゆるやかになる（Schoenfeld ほか 2017、Pelland ほか 2024）
- セット数が同じなら、頻度（週1回か2回か）による筋肥大の差は小さい。筋力は頻度が多いほど伸びやすい（Schoenfeld ほか 2016・2019、Pelland ほか 2024）
- 全身法・上下分割・PPLは、週のセット数がそろっていれば大きな差はない。行ける日数で選ぶ
- 筋肉は幅広い回数（おおむね5〜30回）で育つ。限界の1〜3回手前まで追い込めば十分。筋力には重め（3〜6回）が有利（Schoenfeld ほか 2021、Robinson ほか 2024）
- 初心者は週2〜3回、8〜12回で挙げられる重さから（ACSM 2009）
- 重さは小さな刻みで上げる（目安2〜10%、ダブルプログレッション）
- デロード（軽めの週）は4〜8週に1回が一般的（Bell ほか 2023。研究の証拠より現場の合意）

### 1. 分割法（アプリが選ぶ）
| 週の日数 | 分割法 |
|---|---|
| 1日 | 全身法×1 |
| 2日 | 全身法×2 |
| 3日 | 全身法×3（経験1年以上で希望があればPPL×1） |
| 4日 | 上半身・下半身×2 |
| 5日 | 上半身・下半身・プッシュ・プル・脚 |
| 6日 | PPL×2 |
| 7日 | 6日として扱い、1日は休みにする |

- 経験が「初めて」「1年未満」の人は、行ける日が多くても週3〜4日に抑える（多い分は休みか軽い有酸素を提案する）
- チャットで分割法の変更を頼まれたら、その分割法で組み直す
- 日の並びは、同じ部位を鍛える日の間を48時間以上あける（同じ日の中で同じ部位・似た部位の種目を複数やるのは問題ない）。行ける曜日が連続していて間隔をあけられない場合は、連続する日に違う部位が来る分割法の並びにする

### 2. 日ごとの枠
各日を「枠」の並びで表す。枠は動きの種類で決まり、AIが枠ごとに種目を1つ選ぶ。複数の関節を使う種目の枠を先に置く。

| 日の種類 | 枠（並び順） |
|---|---|
| 全身 | スクワット系 → 水平に押す → 水平に引く → ヒンジ系 → 上に押すか上から引く（日替わり） → 腕か腹（日替わり） |
| 上半身 | 水平に押す → 水平に引く → 上に押す → 上から引く → 横肩 → 二頭 → 三頭 |
| 下半身 | スクワット系 → ヒンジ系 → 片脚かマシン → 裏もも → ふくらはぎ → 腹 |
| プッシュ | 水平に押す → 上に押す → 胸の単関節 → 横肩 → 三頭 |
| プル | 上から引く → 水平に引く → 後ろ肩 → 二頭 → 二頭か前腕 |
| 脚 | スクワット系 → ヒンジ系 → 片脚かマシン → 裏もも → ふくらはぎ → 腹 |

- 1回の時間に収まらない場合は、後ろの枠から削る（1セット＝休憩込みで約3分として計算）

### 3. 量・回数・休憩
| 経験 | 部位ごとの週のセット数 |
|---|---|
| 初めて・1年未満 | 8〜12 |
| 1〜3年 | 10〜16 |
| 3年以上 | 12〜20 |

| 目標 | 複数関節の種目 | 単関節の種目 |
|---|---|---|
| 筋肥大 | 6〜10回・休憩2〜3分 | 10〜15回・休憩60〜90秒 |
| 筋力アップ | メイン種目は3〜6回・休憩3〜5分、他は6〜10回・休憩2分 | 10〜12回・休憩60〜90秒 |
| 減量・健康維持 | 8〜12回・休憩90秒 | 12〜15回・休憩60秒 |

- 初めて・1年未満の人は、目標にかかわらず8〜12回（単関節は10〜15回）から始める
- 1種目のセット数は2〜4
- 週のセット数は、主に使う部位を1、補助で使う部位を0.5として数える（例：ベンチプレスは胸1・三頭0.5・前肩0.5）

### 4. 種目の選び方（AIの役割）
- 枠の動きに合う種目の候補（使える器具・ケガで絞ったもの）から1つ選ぶ
- 重さを伸ばしていけるように、前の週と同じ種目を続ける。変えるのは、伸びが止まったとき、本人が頼んだとき、ケガや器具の事情があるときだけ
- 選んだ理由を短く説明する

### 5. 重さの決め方（アプリの役割）
種目ごとに次の順で決める。
1. **前回の記録がある**：「6. きつさによる調整」に従う
2. **記録はないが、プロフィールに「重量×回数」がある**：推定1RM（Epley式：重量×(1＋回数÷30)）を出し、目標回数に合わせた割合（5回≒87%、6回≒85%、8回≒80%、10回≒75%、12回≒70%、15回≒65%）を掛けて、刻み幅で丸める
3. **どちらもない**：初期値（20kg。ダンベルやマシンも同じ）にし、チャットで「最初は軽めの重さで試して、きつさを記録して」と伝える

回数のみ・時間の種目は重さを扱わない（回数のみの種目の加重は前回の値を引き継ぐ）。

### 6. きつさによる調整
材料は種目ごとの「きつさ（1：楽〜5：限界）」と、目標回数に届いたかどうか。1回の結果ではなく、その種目の直近2回の流れで判断する。

| 状況 | 次回の重さ（アプリ） | 来週のセット数（AIに伝える） |
|---|---|---|
| 楽（1〜2）が2回続いた | 刻み幅2つ分（目安5%）上げる | それでも楽が続くなら1セット増やす（週のセット数の上限まで） |
| 全セットで目標回数に届いた（きつさ3以下） | 刻み幅1つ分上げる | そのまま |
| 目標回数に届いた、きつさ4 | 据え置き | そのまま |
| 目標回数に届かなかった、またはきつさ5が2回続いた | 5〜10%下げる（刻み幅で丸める） | 1セット減らす（2セットより下にはしない） |
| きつさの記録がない | 目標回数に届いたかだけで判断する（届けば刻み幅1つ分上げる） | そのまま |

- 重さを上げるときは、目標回数の下限から再スタートする（ダブルプログレッション）
- 同じ重さで3回続けて目標回数に届かなかったら、10%下げてやり直す

### 7. デロード
- 6週に1回、または「きつさ5が多くの種目で続く」「調子が低い日が続く」ときに、AIが軽めの週を提案する
- 軽めの週は、セット数を約半分、重さは据え置き

## 画面

### 下部メニュー
「ホーム／AIコーチ／メニュー／体／設定」の5つ。「種目」の一覧は「メニュー」画面の中に移す（マイメニューと種目をタブで切り替える）。

### プロフィールの聞き取り（初回）
AIコーチを初めて開いたときに表示する。設定からいつでも変えられる。
- 目標：筋肥大／筋力アップ／減量／健康維持
- 経験：初めて／1年未満／1〜3年／3年以上
- 週の回数（1〜7）、1回の時間（分）、行ける曜日
- 使える器具：ジムのフリーウェイト／ジムのマシン／自宅のダンベル／自重のみ（複数選択）
- ケガや痛む所（自由記入）
- 今の重量（任意）：ベンチプレス・スクワット・デッドリフト・オーバーヘッドプレスの「重量×回数」。記録がある種目は記録を優先する

### AIコーチ画面
- 普通のチャット。メッセージと返事を時系列で表示する
- よく使う依頼はボタンにする：「来週のメニューを作って」「今日できなかった」「今週を見直して」
- AIがメニューを提案したら、チャットに**メニュー案カード**を出す
  - 上部に分割法（例：上半身・下半身×2）
  - 曜日ごとに：タイトル（例：上半身）、種目、セット×回数、休憩時間、重さ（アプリが計算したもの）
  - 部位ごとの週のセット数
  - AIが書いた理由
  - チェックで見つかった注意点（あれば）
  - 「反映する」ボタン。押すと、その日付の予定メニューとして保存する。すでに予定がある日は置き換える（置き換える日を確認画面で示す）
- 通信中は「考え中…」を表示する。失敗したら理由を出して、もう一度送れるようにする
- 合言葉が未設定・不一致のときは、設定へ案内する

### トレーニング画面：きつさの入力
- その種目の最後のセットにチェックしたとき、その種目のカードに「きつさは？」と `1 楽` 〜 `5 限界` のボタンを出す。1回タップで保存する。答えなくても先に進める
- 📝のメモ画面からも、今まで通り入力・変更できる

## AIとのやりとり

### 流れ
1. アプリが、プロフィールと記録から**骨組み**を作る（分割法、日付ごとの日の種類、各日の枠、枠ごとのセット数・回数・休憩、部位ごとの週のセット数の目標、きつさによるセット数の増減）
2. サーバー経由でAIに、骨組み・種目の候補・記録の要約・チャットを渡す
3. AIが、枠ごとに種目を選び、必要なら骨組みの範囲内で調整し、理由を書く
4. アプリが重さを計算し、チェックしてからカードで見せる

### AIに渡す情報
- プロフィール
- 骨組み（上記1）
- 枠ごとの種目の候補（ID・名前・器具。使える器具とケガで絞ったもの）と、前の週にその枠で使った種目
- 直近4週間の記録の要約：日付、種目、セットの重量×回数、きつさ、その日の調子、予定があったのに実施しなかった日
- 対象週の既存の予定
- 守るルール（上記「メニューの決め方」の要点）
- 直近のチャット履歴（最大20件）

### AIから受け取る形
決まった形のJSONで受け取る（Gemini の構造化出力を使う）。
- `message`：チャットに表示する文章
- `proposal`（任意）：メニュー案
  - `split`：分割法
  - `days[]`：`date`（YYYY-MM-DD）、`title`、`exercises[]`（`slot`、`exerciseId`、`sets`、`reps`、`restSec`）、`note`
  - `reasons`：この構成にした理由

### メニュー案のチェック（アプリ側）
見せる前に確認する。
- 種目IDが候補にある（枠の動きに合っている）
- セット 1〜10、回数 1〜30、休憩 0〜300秒
- 日付が対象週の中で、行ける曜日になっている
- 同じ部位の日の間が48時間以上あいている
- 1日の合計時間が1回の時間に収まる（1セット＝約3分）
- 部位ごとの週のセット数が目標の範囲（主に使う部位1、補助0.5で数える）

問題があれば、その内容をAIに伝えて自動で1回だけ作り直してもらう。それでも直らなければ、注意点としてカードに表示する（反映はできる）。

## 種目データへの追加
今の種目一覧に次の情報を足す（定番種目には最初から入れる。自分で追加した種目は編集画面で選べるようにする）。
- 動きの種類：スクワット系／ヒンジ系／片脚／水平に押す／上に押す／水平に引く／上から引く／胸の単関節／横肩／後ろ肩／二頭／三頭／裏もも／前もも／ふくらはぎ／腹／有酸素
- 主に使う部位（1つ以上）と補助で使う部位（0個以上）。部位は：胸／背中／前肩／横肩／後ろ肩／二頭／三頭／前もも／裏もも／お尻／ふくらはぎ／腹
- 複数関節か単関節か

## 裏側の作り

### Vercel への引っ越し
- GitHub の `tktk-h/kintore` を Vercel につなぎ、`main` に上げると自動で公開されるようにする
- アプリ（静的ファイル）とサーバー（`/api/coach`）を同じ場所に置く
- GitHub Pages の自動公開は止める
- 記録の移行：古いURLで「バックアップを書き出す」→ 新しいURLで「読み込む」。ホーム画面のアイコンも新しいURLで追加し直す

### サーバー（`/api/coach`）
- 受け取るもの：合言葉、AIに渡す情報
- 合言葉を環境変数 `COACH_PASSCODE` と照合する。違えば 401
- 環境変数 `GEMINI_API_KEY` で Gemini を呼び、結果をそのまま返す
- 1回のリクエストの大きさに上限を設ける（大きすぎれば 413）
- APIキーや合言葉はログに出さない
- AIの呼び出し部分は1つのファイルにまとめ、別のAIに乗り換えるときはそこだけ替えればよい作りにする
- 骨組みの作成・重さの計算・チェックはアプリ側（ブラウザ）で行う。サーバーはAIの中継だけをする

### アプリ側のデータ
| データ | 内容 |
|---|---|
| Profile（プロフィール） | 聞き取りの内容。1件だけ |
| ChatMessage（チャット） | 役割（自分/AI）、本文、メニュー案（あれば）、反映済みかどうか、日時 |
| Exercise | 動きの種類、主に使う部位、補助で使う部位、複数関節かどうかを追加する |
| PlannedWorkout | 作成元に `ai` を追加する。各種目に枠と目標回数の幅を持たせる |
| Settings | 合言葉を追加する |

すべて今まで通り端末内（IndexedDB）に保存し、バックアップの対象にも含める。DBのバージョンを1つ上げ、既存の定番種目には新しい情報を書き足す（既存の記録はそのまま）。

## エラー処理
- 通信できない・サーバーエラー・合言葉の不一致・AIの返事が決まった形でない：それぞれ分かる言葉で表示し、送った内容は消さずに再送できるようにする
- Gemini の無料枠の上限に達した：「今日は上限に達しました。時間をおいて試してください」と表示する
- オフラインのときは送信ボタンを押せないようにし、理由を表示する

## テスト
- 分割法と日の並びの決定、枠と量の決定、重さの計算、きつさによる調整、メニュー案のチェック、AIに渡す情報の組み立て、返事の読み取りは、ユニットテストを書く（調整は表のすべての行をテストする）
- サーバーは、Gemini の呼び出しを差し替えて、合言葉の照合・エラーの返し方をテストする
- チャット画面は、サーバーの返事を差し替えて「送信 → カード表示 → 反映 → 予定に入る」をテストする
- トレーニング画面は、最後のセットにチェック → きつさを選ぶ → 保存される、をテストする
- 最後に、本物の Gemini でメニューを作り、iPhone で反映から実行まで確認する
