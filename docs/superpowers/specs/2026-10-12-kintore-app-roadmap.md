# 筋トレアプリ 全体計画（ロードマップ）

作成日: 2026-10-12

## 目的
自分が毎日使える筋トレ・食事・体の記録アプリを作る。うまく作れたら他の人にも使ってもらう。ポートフォリオ作品。

## 基本方針
- **入力をとにかく簡単に**：前回の値を自動入力し、同じなら✓だけで済むようにする。めんどくさくならない工夫を最優先にする
- **初心者でも迷わない**：何を・何回・どれくらい休むかまでわかるようにする
- 作りながら便利そうな機能を思いついたら相談して決める（勝手に追加しない）

## 技術
| 項目 | 決定 |
|---|---|
| 形態 | PWA（スマホのホーム画面に追加できるWebアプリ） |
| フロント | React + TypeScript + Vite |
| 保存 | 端末内（IndexedDB）から始める。後でクラウド同期できる設計にしておく |
| サーバー | フェーズ1b（AI）で初めて用意する（APIキーを隠すため） |
| 端末 | iPhone（バイブ不可。通知はホーム画面追加＋サーバーからのプッシュ） |

## 機能一覧

### ① 記録
- トレーニング：種目、重量、回数、セット数
  - 記録形式は3種類：重量×回数／回数のみ（自重。加重・補助あり）／時間・距離（有酸素）
  - 対象：フリーウェイト、マシン、自重、有酸素・スポーツ
- 種目ごとのメモ：きつさ、気づき
- その日全体：調子、満足度、メモ
- 体：体重、体脂肪率、写真
- 食事：食べたもの。自炊の場合は食材ごとに細かく入力

### カレンダー（記録の見え方）
- 記録はカレンダーを中心にまとめて見る
- 日付ごとに鍛えた部位をマークで表示する
- 日付をタップすると、その日に入力したすべての情報（トレーニング、メモ、調子、体、食事）が見られる

### ② 分析・振り返り
- 種目ごとの重量推移グラフ
- 自己ベスト（PR）の自動検出
- 推定1RM
- 部位ごとのトレーニング量、部位ヒートマップ

### ③ ジムで使う道具
- 休憩タイマー（音・バイブで通知）
- インターバルタイマー
- プレート計算
- ウォームアップセットの計算

### ④ 種目ガイド
- 種目ごとに鍛えられる筋肉、コツ、説明動画へのリンク

### ⑤ AI
- トレーニングメニュー作成：その人に合わせて種目、セット数、回数、休憩時間まで決める
- 食事メニューの提案
- 食事写真からカロリー・栄養素を推定
- メニュー（トレーニング・食事）の相談チャット
- 週ごとの振り返り（トレーニング、食事、体重を読んでコメント）
- マシンが埋まっている時の代わりの種目の提案

### ⑥ 習慣化・ゲーム化
- 連続日数、週の目標
- レベル・経験値
- 実績バッジ
- 総挙上重量の例え

### ⑦ クラウド同期・ログイン
- ログイン、複数端末での同期

## 作る順番
1a. **記録の基盤**：トレーニング・体の記録、カレンダー、休憩タイマー、種目データベース、マイメニュー、予定メニュー、バックアップ（[設計書](2026-10-12-phase1a-recording-design.md)）
1b. **AIメニュー作成**：Vercelに引っ越してサーバーを用意する。プロフィールの聞き取り、アプリ内のAIチャット（Gemini）、AIが1週間分のメニューを作り確認して予定に反映（[設計書](2026-10-13-phase1b-ai-coach-design.md)）。休憩終了の通知は別のタイミングで作る
2. **食事の記録**：食べたもの、自炊の食材入力
3. **分析・振り返り**
4. **種目ガイドとジムで使う道具**
5. **残りのAI機能**：食事メニュー提案、食事写真の解析、週ごとの振り返り、代わりの種目の提案

### AIメニューの質の担保（1b）
1. 最初にしっかり聞き取る（目標、経験、頻度・時間、器具、ケガ、今の挙上重量）
2. 根拠のあるトレーニング理論をルールとしてAIに守らせる
3. 重量は実際の記録からアプリが計算する（AIに推測させない）
4. AIが作ったメニューをアプリがチェックしてから反映する
5. メニューは週単位のプログラムとして組み、理由も説明させる
6. APIは使った分だけ料金がかかる。公開時は使いすぎを防ぐ仕組みを入れる
6. **ゲーム化**
7. **クラウド同期・ログイン**

各フェーズは、作り始める前に詳細を一緒に決める。
