# フェーズ1a 記録の基盤 設計書

作成日: 2026-10-12
全体計画: [2026-10-12-kintore-app-roadmap.md](2026-10-12-kintore-app-roadmap.md)

## ゴール
自分で組んだメニューを使って、iPhoneでジムのトレーニングを記録し始められる状態にする。AIは使わない（AIはフェーズ1bで追加する）。

## 範囲
**含む**: ホーム画面、予定メニューとトレーニング実行、セット記録、休憩タイマー、メモ・きつさ・調子・満足度、体の記録（体重・体脂肪率・写真）、カレンダー、種目データベース、マイメニュー、バックアップ（書き出し・読み込み）

**含まない**: AI、サーバー、通知、ログイン、グラフ、食事の記録

## 前提
- 利用端末は iPhone。ホーム画面に追加して使う（PWA）
- データはすべて端末内（IndexedDB）に保存する

## 画面と機能

### 1. ホーム画面
上から順に次を表示する。
- **今日の体重**：未記録なら「記録する」ボタン、記録済みなら値を表示
- **今日のトレーニング**：状況によって表示を変える
  - 予定メニューがある：「今日のトレーニングを始める」を大きく表示し、予定の種目一覧も見せる
  - 予定がない：「前回のメニューで始める」「マイメニューから選ぶ」「空から始める」
  - トレーニング中：進み具合（例：3/5種目）と「続ける」
  - 終了後：今日のまとめ（時間、総重量、自己ベスト）
- **カレンダー**（月表示）

### 2. トレーニング実行画面
- 種目ごとに、前回の記録（例：「前回 60kg × 8, 8, 7」）と休憩時間を表示する
- 各セットの行に、予定の重量と回数をあらかじめ入れておき、横にチェックボックスを置く。終わったらチェックするだけで記録できる
- 予定がない種目は、前回の値を最初から入れておく
- 数字をタップすると＋−ですぐ変えられる（重量は2.5kg刻み、回数は1回刻み。刻み幅は設定で変更できる）
- セットの追加・削除はワンタップでできる
- 種目の追加・削除・並べ替えができる
- 記録の形式は種目によって3種類：
  - 重量×回数（フリーウェイト、マシン）
  - 回数のみ（自重。加重・補助の重さも入力できる）
  - 時間・距離（有酸素、プランクなど）
- **種目ごとのメモ**：種目名の横の📝から、きつさ（5段階）と自由メモを入力できる（任意）
- **終了時**：「調子」（顔マーク5段階）、「満足度」（5段階）、メモを入力できる（すべて任意）

### 3. 休憩タイマー
- セットをチェックすると、その種目の休憩時間でタイマーが自動で始まる
- 休憩中は画面が消えないようにし（Screen Wake Lock）、大きなカウントダウンを表示する
- ±15秒、スキップのボタンを置く
- 休憩中もアプリ内の他の画面に移動できる。その間はタイマーを小さなバーとして表示し続ける
- **音は鳴らさない**（ジムで周りの迷惑になるため）。終了したら画面を光らせて知らせる
  - iPhoneのWebアプリはバイブ機能が使えないため、1aではこれが限界
- 終了時刻を保存しておき、アプリを閉じたり他のアプリを使ったりしても、戻ってきたときに残り時間を正しく表示する
- 他のアプリを使っている間や画面を消している間の通知は、サーバーを用意してから追加する（iPhoneの通知は本体のマナーモードの設定どおりにバイブする）

### 4. 体の記録
- 体重、体脂肪率、写真（任意）
- 前回の値を最初から入れておき、＋−で調整できる
- 写真は端末内に保存し、2枚を並べて比較できる

### 5. カレンダー
- 月表示。トレーニングした日には、鍛えた部位を色の点で表示する
- 予定メニューがある日には、予定のマークを表示する
- 日付をタップすると、その日の記録をすべて表示する（トレーニング、メモ、調子、満足度、体重、体脂肪率、写真）
- 未来の日付をタップすると、予定メニューを確認・割り当てできる

### 6. 種目データベース
- 定番の種目を50〜80種目ほど最初から入れておく
- 項目：名前、部位（胸、背中、脚、肩、腕、腹、有酸素）、器具、記録形式、標準の休憩時間
- 自分で種目を追加・編集できる
- 種目名で検索できる。部位で絞り込める

### 7. マイメニュー
- 種目、セット数、回数、重量、休憩時間の組み合わせを名前をつけて保存する（例：「胸の日」）
- マイメニューを日付に割り当てると、その日の予定メニューになる
- 終わったトレーニングから「マイメニューとして保存」もできる

### 8. バックアップ
- 全データ（写真を含む）を1つのファイルに書き出す
- そのファイルから読み込んで復元する。読み込む前に確認を表示する

## データ構造
後でクラウド同期とAIを追加できるように、次の方針で設計する。
- すべての記録にIDとして UUID を使う
- すべての記録に作成日時・更新日時を持たせる
- 削除は削除フラグで行う（同期で削除を伝えられるようにするため）

主なデータ：
| データ | 主な項目 |
|---|---|
| Exercise（種目） | 名前、部位、器具、記録形式、標準の休憩時間、ユーザー追加かどうか |
| Routine（マイメニュー） | 名前、種目ごとの予定（セットごとの重量・回数、休憩時間） |
| PlannedWorkout（予定メニュー） | 日付、種目ごとの予定、作成元（マイメニュー／手動。1bでAIを追加） |
| Workout（実施したトレーニング） | 日付、開始・終了時刻、調子、満足度、メモ、元にした予定 |
| WorkoutExercise | 種目、順番、きつさ、メモ |
| Set（セット） | 重量、回数、加重・補助の重さ、時間、距離、完了したかどうか |
| BodyLog（体の記録） | 日付、体重、体脂肪率、写真 |
| Settings（設定） | 重量の刻み幅、単位など |

予定メニューと実施したトレーニングは別のデータにする。予定を誰が作ったか（自分かAIか）に関係なく、実行画面は同じものを使えるようにするため。

## 技術構成
- React + TypeScript + Vite
- PWA：vite-plugin-pwa（オフラインでも動くようにする）
- 保存：IndexedDB（ライブラリは Dexie.js）
- 画面遷移：React Router
- テスト：Vitest + React Testing Library

## エラー処理
- 保存に失敗したら画面に知らせ、入力した内容は消さずに残す
- バックアップの読み込みは、ファイルの形式を確認してから行う。不正なファイルなら何も変更しない
- 保存容量が少なくなったら知らせる（写真が増えたとき用）

## テスト
- 計算やデータ処理（前回の記録の取得、総重量、自己ベスト、休憩タイマーの残り時間、バックアップ）はユニットテストを書く
- トレーニング実行画面の主な操作（チェック、数値変更、セット追加）は画面のテストを書く
- 最後にiPhoneの実機で、ホーム画面への追加、オフライン動作、休憩タイマーを確認する
